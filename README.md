# SockLock Hook Variations

Локальний інструмент для motion-дизайнера. Один вертикальний MP4 і CSV з трьома вступними фразами дають три готові відеоваріації. Напис з’являється лише протягом перших трьох секунд. Решта відеоряду та аудіо беруться з вихідного ролика.

## Швидкий старт

Потрібні Node.js 18.11 або новіший, FFmpeg і FFprobe в PATH, Python 3 із Pillow. Збірка FFmpeg має підтримувати фільтр `overlay` і кодек `libx264`.

Якщо Pillow ще не встановлено, підготуй локальне середовище:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export PYTHON_BIN="$PWD/.venv/bin/python"
```

З папки проєкту запусти:

```bash
node render.mjs --demo
```

У `out/` з’являться `laundry.mp4`, `pair.mp4` і `small-change.mp4`. Це три варіації синтетичного 12-секундного ролика SockLock. Відео та hooks позначено як синтетичні. Демо працює локально та не потребує API-ключів.

У репозиторії також є реальний тестовий ролик із трьома українськими hooks:

```bash
node render.mjs \
  --video examples/laundry-base.mp4 \
  --csv examples/laundry-hooks-uk.csv \
  --out out-laundry
```

Джерело відео, автор і посилання на ліцензію Pexels наведені в
`examples/laundry-source.md`. Готові файли з’являться в `out-laundry/` і не
додаються до Git, оскільки їх можна повторно згенерувати цією командою.

Якщо Pillow уже встановлено в іншому Python, можна передати його шлях у `PYTHON_BIN`. CLI також розпізнає `CODEX_PRIMARY_RUNTIME_PYTHON`, якщо ця змінна вже задана.

## Власний ролик

```bash
node render.mjs --video base.mp4 --csv hooks.csv --out out-custom
```

Вхідний ролик має бути MP4 тривалістю від трьох секунд із вертикальним кадром 9:16, парними розмірами в пікселях і без метаданих повороту. Залиши на початку місце під напис у верхній частині кадру. Для першого пілоту використовуй шаблон без уже вшитого вступного тексту.

CSV має бути в UTF-8. Перший рядок — `id,hook`. ID стає назвою вихідного файла, тому використовуй унікальні малі латинські літери, цифри й дефіси. Один hook займає один рядок CSV і має максимум 72 символи. Поля з комою бери у подвійні лапки.

```csv
id,hook
laundry,Still losing socks in the wash?
pair,"Same wash, still a pair?"
small-change,A small change to laundry day
```

Перевірка помилкового рядка:

```bash
node render.mjs --demo --edge --out out-edge
```

У цьому режимі четвертий hook задовгий. CLI пояснює, який рядок пропустив, і зберігає три валідні варіації. Якщо вказати ту саму вихідну папку повторно, успішні рендери з тими самими ID замінять попередні файли.

## Як це працює

1. `render.mjs` читає CSV, перевіряє поля та бере розміри вхідного відео через FFprobe.
2. `visuals.py` підбирає розмір шрифту, розкладає hook на рядки й зберігає прозорий PNG.
3. FFmpeg накладає цей PNG від початку ролика до позначки 3 с і кодує результат у H.264. Аудіодоріжки за наявності копіюються з джерела.
4. CLI друкує шляхи до готових файлів і кількість пропущених рядків.

Щоб заново зібрати базовий синтетичний ролик із локальних ілюстрацій, запусти `"${PYTHON_BIN:-python3}" visuals.py demo examples/synthetic-base.mp4`.

## Що перевірити в пілоті

Дай дизайнеру той самий базовий ролик і три готові hooks. Порівняй активний час ручного монтажу та роботи через CLI, включно з експортом і рев’ю трьох MP4. Це перевіряє економію часу на виробництві. Рекламний ефект вимірюй окремим тестом.
